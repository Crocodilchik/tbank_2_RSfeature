# Yambda: RL-дообучение последовательной GPT-2

Исследовательский проект: обучение рекомендательной модели на идентификаторах треков, построение reward model и сравнение четырёх вариантов оптимизации с baseline. Используется Yambda, файл `flat/50m/multi_event.parquet` из набора [yandex/yambda](https://huggingface.co/datasets/yandex/yambda).

Репозиторий содержит исходники, конфигурации, тесты и методику. Датасеты, установленные окружения, веса, прогнозы, журналы, технические отчёты и исходные локальные материалы в Git не включаются. При запуске они создаются относительно каталога проекта.

## Требования

- Windows и PowerShell.
- Доступный инструмент `uv`; установщик не устанавливает его глобально.
- Интернет для получения Python, пакетов и исходного датасета.
- Для исследовательской конфигурации: GPU NVIDIA с совместимым драйвером CUDA 12.8. Исходный ресурсный профиль — RTX 3050 Laptop 4 GB и около 16 GB RAM.

Python 3.12.14 устанавливается в `.python/`, пакеты — в `.venv/`, кеши и временные файлы — в `.cache/` и `.tmp/`. `project_env.ps1` создаёт локальные рабочие каталоги и задаёт пути дочерним процессам. Версии зависимостей зафиксированы в `requirements.lock.txt`; CUDA-сборка PyTorch устанавливается отдельно из официального wheel index.

## Быстрый запуск

Выполните из каталога своей копии проекта:

```powershell
.\install.ps1
.\run.ps1 -Mode test
.\run.ps1 -Mode smoke
```

`smoke` — короткая техническая проверка всех методов. Её метрики не являются научным подтверждением превосходства моделей. Для основного исследования:

```powershell
.\run.ps1 -Mode study
```

`smoke` и `study` сначала сохраняют локальный снимок текущего кода в `artifacts/code/`, необходимый последующей аналитике. Загрузчик фиксирует revision Hugging Face и SHA-256 исходного parquet. Уже существующий файл с неверной контрольной суммой не заменяется молча.

Каталог запуска имеет вид `experiments/<config_hash12>_<code_hash8>/`. Точный путь печатается в журнале; идентификатор меняется вместе с конфигурацией или исходниками. Для дальнейших команд подставьте имя своего завершённого запуска:

```powershell
$RunDirectory = 'experiments/<идентификатор_вашего_запуска>'
.\run.ps1 -Mode controls -Run $RunDirectory
.\run.ps1 -Mode compare -Run $RunDirectory
```

`controls` выполняет дополнительные контрольные оценки и обучает отсутствующие контрольные модели. `compare` читает сохранённые результаты, строит статистику и исполняемый notebook; основную матрицу он не переобучает. Дополнительные разделы включаются после завершения контролей. Основной финальный документ — `reports/comparison.ipynb`; вся папка `reports/` локальна и исключена из Git.

Другие режимы: `prepare` — только подготовка study-данных; `benchmark` — синтетический замер скорости и CUDA-памяти. Чтобы вызвать Python-модуль напрямую, сначала выполните `. .\project_env.ps1` и используйте `.\.venv\Scripts\python.exe`.

## Методы

| Имя | Метод |
|---|---|
| B0 | GPT-2 на item-ID, next-item cross-entropy, tied embeddings |
| A1 | B0 и reranking кандидатов по прогнозу RM, без обучения новой GPT-2 |
| A2 | REINFORCE и KL-штраф относительно замороженной B0 |
| A3 | A2 со штрафом за расхождение reward ensemble |
| A4 | REINFORCE для списка с uncertainty/redundancy penalty |
| control_sft | Дополнительное supervised-обучение B0 на блоке R |

Это процедуры с общим backbone, обученным с нуля; текстовые pretrained-веса GPT-2 не используются. Отдельный CatBoost служит диагностическим оценщиком и не оптимизируется политикой.

## Методика и границы выводов

См. [контракт данных](docs/data_contract.md), [политику времени](docs/point_in_time_policy.md), [план экспериментов](docs/experiment_plan.md) и [исследовательскую постановку](docs/research_design.md).

Временные блоки F/C/R/V/T разделяют fit, калибровку RM, RL, выбор параметров и финальную оценку. История строго предшествует запросу; одновременные события не входят друг в друга. Каталог строится только в F, неизвестные test targets остаются с нулевым попаданием. Метки доли проигрывания имеют документированный консервативный буфер созревания: точного completion timestamp в исходнике нет.

Основная конфигурация ограничивает число окон и выбирает пользователей по стабильному хешу. В исходном исследовании получилось 931 пользователь и 166104 трека начального каталога; это не обучение на всех 50M событиях. Настройки выбираются на V seed42 и фиксируются для43/44. Помимо native выдачи сохраняется common Next-K, поскольку способ генерации влияет на сравнение.

RM-score — модельный proxy, а не измеренное удержание или причинный эффект новой политики. Ансамблевая дисперсия не является гарантированной доверительной границей. Дополнительные абляции одного seed имеют описательный статус; их бюджет не выровнен с основной матрицей по GPU-секундам.

## Локальные результаты и Git

`.gitignore` исключает все данные, веса, кеши, отчёты, notebooks и рабочие скрипты разработки. Они остаются на диске. Файлы установки, `project_env.ps1`, конфигурации и lock-файл отслеживаются: это рецепты воспроизведения, а не установленное окружение.

Технические отчёты `full_report*.md`, `docs/project_status.md` и `docs/resource_decision.md`, исходные локальные материалы и одноразовые утилиты миграции в публичную копию не входят. Новая копия воспроизводит эксперименты самостоятельно; готовые локальные веса и отчёты из неё автоматически не появятся.

Исходный код распространяется по лицензии [MIT](LICENSE). Этот проект не распространяет Yambda: условия использования исходного набора определяются его владельцем.
