# Политика времени и доступности, версия 1

Эта политика относится к новому проекту. Подтверждения предыдущего проекта не являются разрешениями на действия здесь.

1. История запроса T состоит из реальных прослушиваний с timestamp<T. Все события одного timestamp имеют один префикс. Технический порядок item-ID не является доказанным порядком одновременных действий.
2. Текущая доля прослушивания, текущие реакции и будущие значения не являются признаками. Прежние доли прослушивания исключены из первой реализации: время их фактической доступности не установлено. Исторические item-ID трактуются как доступные после записанного временного интервала; это явное допущение, а не доказательство наличия completion timestamp.
3. Длительность кандидата доступна только после первого наблюдения до T в начальном блоке F. Нет обратного заполнения из target-строки. Противоречивость длительности проверяется отдельно.
4. Словарь и каталог построены в F. Это параметры end-to-end модели; не выдаются за заранее доступные fitted признаки ранних F-примеров. Неизвестные исторические ID имеют отдельный UNK, не padding.
5. F используется для fit B0/RM; C для калибровки RM; R для RL; V для выбора; T для финальной оценки. Равные timestamps не разрезаются. Веса RM и B0-reference заморожены в R.
6. В V/T допускается общий реальный replay по строго прошлым событиям. Обновления весов на T запрещены.
7. Синтетические рекомендации хранятся отдельно от реальной истории. RM оценивает каждый кандидат по исходной реальной истории. A4 оптимизирует slate, а не симулирует доказанное потребление/удержание.
8. Непрослушанный объект не получает метку отказа. Измеренные реакции доступны только на logged actions. Нет заявлений о причинном эффекте или несмещённом OPE.
9. Будущие positives не используются для отбора train negatives, weights, кандидатов и изменения каталога. Основная оценка не добавляет неизвестный target в каталог.
10. Проверки: mutation будущего/target, ties, padding, независимость batch, frozen reference, общность query registry. Полная проверка provenance и availability необходима до маркировки final research.
## Дополнение версии 2: созревание reward-меток

Первый предварительный запуск остановлен до test и помечен superseded_before_test. Его результаты не входят в финальное сравнение.

Для каждой метки вычисляется reward_available_at = timestamp + max(reward_guard_units, ceil(track_length_seconds * played_ratio_pct /100)). В основной конфигурации reward_guard_units=86400 исходных единиц. Единицы исходных часов сохраняются; это консервативная модель задержки, не наблюдённое время завершения и не гарантия при неограниченных паузах.

RM обучается в F только на метках reward_available_at<конецF. Калибровка использует только созревшие к концуC метки. То же правило применяется к диагностическому оценщику и оценке RM в V/T. События listen-ID по-прежнему могут быть историей после своего recorded timestamp: будущая доля прослушивания во входах не используется. Обычный SFT на next-item ID не фильтруется по reward_eligible. Positive-only control использует только созревшие reward labels периодаR.

Эта норма имеет приоритет над предыдущими сокращёнными формулировками про label availability. Фактические данные не содержат отдельного достоверного completion timestamp; это ограничение остаётся явно обозначенным.
